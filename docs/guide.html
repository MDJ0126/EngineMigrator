현재 상태사용 방법대입 규칙다중 장면·프리팹스크립트 범위실행 검증로컬 LLM남은 작업
장면·지원 리소스·제한된 게임 로직을 실제 프로젝트로 생성합니다. 전체 게임 자동 포팅은 미완료입니다.

원본과 선택한 대상은 보존합니다. 독립 복사본에서 코드 컴파일, 객체·에셋 연결, 저장 후 재열기를 수행합니다. 검사 통과, 코드 생성, 저장 검증, 실제 실행 대조는 각각 다른 결과입니다.

01 · 현재 가능한 작업

장면·리소스

PNG/JPEG/TGA, 기본 URP Lit/Unlit 및 Standard/Unlit, 단일 서브메시, 계층·좌표, 카메라·방향광·일부 후처리·환경을 대상 엔진의 실제 객체로 만듭니다. Read/Write가 꺼진 FBX 메시도 에디터에서 읽습니다.

상태·상속·이동

제한된 MonoBehaviour 클래스를 Runtime Actor로 컴파일하고 장면 객체에 연결합니다. 인스턴스 값, private SerializeField, GameObject 참조, Vector3와 월드·로컬 위치 이동을 지원합니다.

양방향 확인

EngineMigrator가 생성한 네이티브 헤더를 실제 코드 본문에서 C#으로 복원하고 Unity 장면에 붙입니다. 엔진 고유 설정의 일부는 왕복 보존용 메타데이터에 남습니다.

02 · 실행과 사용 방법

  1. 원본·대상 프로젝트 폴더와 Unity → Unreal 또는 Unreal → Unity를 선택합니다. 대상은 해당 엔진 버전으로 생성한 프로젝트를 사용하세요.
  2. 사전 검사를 실행합니다. 버전·경로·스크립트 목록과 차단 사유를 확인합니다. 파일 목록이 모두 변환됐다는 뜻은 아닙니다.
  3. 장면·리소스 포팅을 누르고 프로젝트 외부의 결과 폴더를 선택합니다. Unity.exe와 UnrealEditor-Cmd.exe는 프로젝트 버전과 일치해야 합니다.
  4. Source/Target 복사본에서 엔진이 실행됩니다. 지원하는 장면 스크립트가 있으면 Runtime 플러그인을 생성하고 UHT·네이티브 컴파일을 수행합니다. 원본을 자동 업그레이드하지 않습니다.
  5. 성공하면 Target 프로젝트를 엔진에서 여세요. Unreal은 생성 맵을 시작 맵으로 설정하고, Unity는 생성 장면을 빌드 장면으로 설정합니다.
  6. 변환 대응표에서 원본 ID → 대상 에셋·객체 → 참조 ID와 실제 검증 JSON을 확인합니다. 오류가 나면 해당 작업 폴더의 Unity/Unreal 로그를 확인합니다.

‘MonoBehaviour / Actor 클래스 변환’ 메뉴는 클래스만 별도로 변환합니다. 장면 부착과 직렬화 값·참조 연결까지 수행하려면 ‘장면·리소스 포팅’을 사용하세요. 순수 정적 함수 코드 생성과 Blueprint Function Library 변환은 별도 메뉴입니다.

현재 Unity 입력은 활성 빌드 장면 하나가 필요합니다. Unreal 입력은 Config/DefaultEngine.ini에 /Game/ 시작 맵이 필요합니다. 다른 렌더 파이프라인, 동일 이름의 외부 플러그인, 매핑되지 않은 코드·컴포넌트는 오류로 남깁니다.

04 · 지원하는 코드와 차단하는 코드

MonoBehaviour ↔ Actor

float/double/bool/int/GameObject/Vector3 필드, public 및 private/protected SerializeField, 단일 상속, virtual/override와 명시적인 부모 호출을 지원합니다. 숫자·논리식, if/else, while, break/continue, 지역 변수와 포팅 클래스 계층의 함수 호출을 처리합니다.

int 덧셈·뺄셈·곱셈·증감은 C#의 기본 unchecked 오버플로를 유지하도록 생성합니다. 정수 나눗셈·나머지·비트 연산과 임의 형변환은 미지원입니다. Vector3 생성·기본 축·덧셈/뺄셈/스칼라 곱셈·좌표 성분 및 자신의 transform.position/localPosition 대입을 지원합니다.

런타임 Transform 애니메이션 프리팹

Legacy Animation의 지원 Transform 클립을 포함한 프리팹을 생성할 때 재생 Actor도 함께 복제합니다. 각 LevelSequence 바인딩은 원래 프로토타입이 아닌 새 객체 계층으로 연결하고, 인스턴스별 시계로 평가합니다. 프로토타입은 재생하지 않습니다. 실제 테스트는 Loop·Once·ClampForever, 비활성 프리팹의 첫 활성화, 재활성화, 비활성 Animation과 재생 중 객체 복제를 포함합니다.

Unity 기준 실행에서는 생성 프레임의 애니메이션 평가가 0초 자세부터 시작했습니다. 재생 중 객체를 복제하거나 비활성 객체를 다시 활성화해도 내부 재생 시간은 처음부터 시작하지만, 호출 반환 시점의 Transform과 공개 스크립트 필드는 복사됩니다. Update에서 읽은 자세와 이후 프레임 관찰 자세를 모두 대조합니다. Once 종료 뒤 마지막 자세 유지도 확인했습니다. Unity의 Once/Clamp 열거형 별칭은 내보낼 때 Once로 정규화합니다.

객체 전체 삭제 시 소유 재생 Actor를 함께 제거합니다. 장면 전환에서는 월드 정리 콜백으로 재생 시계의 델리게이트를 해제합니다. 재생 중 객체를 남긴 채 다음 장면으로 이동하는 실제 실행도 검사합니다. 정의·프로토타입의 실제 채널과 바인딩을 저장·재열기 후 검증하며, 한쪽만 편집한 경우에는 동기화를 위해 재가져오기가 필요합니다.

검증 대상은 지원되는 Legacy Transform 자동 재생입니다. Animator 상태 기계·스켈레탈 애니메이션·AnimationEvent·블렌딩·임의 재생 제어 API·일반 애니메이션 컴포넌트 조회는 별도 미지원 범위가 남아 있습니다. 물리와 같은 Transform을 동시에 제어하는 조합은 기존 차단을 유지합니다. 런타임 UI 프리팹은 아직 구현 중입니다.

패키지 실행에서는 에디터와 달리 숨겨진 프로토타입까지 재생되는 차이를 발견했습니다. 프로토타입 클래스에서는 자동 재생 이벤트 그래프를 제거하고 평가 대상도 보조 Actor로 격리합니다. 복제본은 생성 후 실제 새 계층으로 다시 연결해 자체 시계로 평가합니다. 에디터 검사만으로 통과 처리하지 않고 패키지의 프로토타입 자세도 매 시점 대조합니다.

물리 프리팹의 런타임 생성과 활성 상태

기존 내보내기에서 지원하는 기본 충돌체·Rigidbody 구성의 런타임 프리팹 생성 경로를 추가했습니다. 실제 테스트는 동적 Box·Sphere, Kinematic Capsule, 비활성 Box 프리팹과 재활성화·삭제를 포함합니다. 충돌체 종류·크기·질량·중력·시뮬레이션 상태·속도와 프리팹/내부 객체 참조를 실행 및 재내보내기로 대조합니다.

Unreal의 장면별 프로토타입은 실제 물리 컴포넌트를 저장하지만 시뮬레이션은 정지합니다. 복제본은 자신의 활성 상태에 맞게 시뮬레이션을 시작하고, 비활성화할 때 속도를 보관해 재활성화 때 복원합니다. 프로토타입과 정의의 물리 속성을 각각 스냅샷으로 검사하므로 한쪽만 변경한 상태로 역변환하면 재가져오기를 요구합니다.

첫 실행에서는 Unreal이 Instantiate한 프레임부터 중력을 적용해 Unity보다 한 물리 단계 앞섰습니다. 변환 스크립트의 Update를 물리 처리 이후 단계로 옮겨 생성 프레임의 위상을 맞췄습니다. 서로 충돌하지 않는 무감쇠 자유낙하 테스트에는 위치 0.0001m, 속도 0.0001m/s 기준을 적용했습니다. 기존 지면 접촉·250프레임 검사의 별도 물리 해석 오차 기준은 유지하며, 두 엔진의 모든 물리 상황이 동일하다는 뜻은 아닙니다.

비활성 루트의 Rigidbody를 복합 충돌체로 잘못 판정한 내보내기 검사도 수정했습니다. 복합 충돌체·비지원 축/모드·임의 물리 API와 충돌 콜백, 물리와 애니메이션/UI를 함께 복제하는 모든 조합은 여전히 미지원 또는 미검증입니다. 런타임 Transform 애니메이션 프리팹은 위 절의 범위에서 지원합니다. UI 프리팹 실행 연결은 별도 구현 항목입니다.

프리팹 정의 간 연쇄·순환 참조

사용자 스크립트의 GameObject 필드가 다른 기본 프리팹 자산의 루트를 가리키는 경우를 지원합니다. 장면에서 A만 참조하더라도 A→B→C→A처럼 연결된 정의를 수집하며, 방문한 자산은 한 번만 구성합니다. 대상이 없는 참조는 가져오기 전에 차단합니다. 중첩 프리팹이나 Variant와는 별개의 자산 필드 참조입니다.

Unreal에서는 같은 장면 안의 비실행 프로토타입을 서로 연결합니다. 생성된 객체에서 다음 프리팹을 조회·생성하고, 순환 경로를 돌아 같은 유형을 다시 생성해도 내부 루트·컴포넌트 참조는 새 복제본으로 연결합니다. Unity가 자기 자신을 가리키는 필드를 저장할 때 내부 루트 참조로 직렬화하는 경우에는 그 내부 참조 의미를 보존합니다. 실제 자산 참조와 내부 참조는 내보낸 종류에 따라 구분합니다.

Unity 복원은 먼저 프리팹 자산의 경로와 식별자를 등록한 뒤 내용을 채우므로, 매니페스트 순서와 무관하게 앞방향·순환 참조를 복원합니다. 복원 후 실제 실행과 재내보내기로 참조·상태를 대조합니다. 비교식 안의 상태 변경 없는 사용자 컴포넌트 GetComponent 조회를 지원하며 AddComponent 같은 상태 변경 호출의 평가 순서 제한은 유지합니다. 런타임 물리 프리팹은 위 절의 범위를 참고하십시오. Transform 애니메이션은 위 절의 범위에서 지원합니다. UI 구성, 중첩·Variant 및 임의 API는 별도 미지원 범위입니다.

비활성 프리팹과 OnDisable 내부 복제

메시·사용자 스크립트로 구성된 비활성 루트·자식 프리팹의 런타임 생성을 지원합니다. 물리 구성은 위 절의 검증 범위에서 추가 지원합니다. 지원 Transform 애니메이션은 위 절의 범위를 참고하십시오. UI·카메라·라이트·Volume을 포함한 런타임 프리팹은 사전 검사를 유지합니다.

실제 Unity 기준으로 비활성 프리팹 생성 직후에는 Awake·OnEnable·Start가 실행되지 않습니다. 루트를 활성화하면 해당 루트의 Awake·OnEnable이 실행되고, 비활성 자식은 자신의 활성화까지 대기합니다. 이미 실행한 객체를 비활성 상태에서 복제하면 공개 필드 값은 복사하지만, 엔진 내부 초기화 상태는 새로 시작합니다. 따라서 공개 Awake·Start 카운터도 이후 콜백에서 다시 증가합니다.

GameObject 삭제 요청의 OnDisable 안에서 복제한 객체와, 계층 비활성화의 OnDisable 안에서 복제한 객체를 실제 실행으로 대조했습니다. 삭제 대기·계층 처리의 임시 태그를 복제본으로 전파하지 않고, 공개 필드와 내부 GameObject·컴포넌트 참조를 복제본으로 연결합니다. 검사한 재활성화·재삭제 흐름의 동등성이며 임의 깊이의 재귀 복제·모든 다른 콜백 조합은 미검증입니다.

GameObject 전체 삭제와 초기 프리팹 복제

Destroy(GameObject)는 컴포넌트 단독 삭제와 구분합니다. 검사한 활성 객체는 삭제 요청 안에서 컴포넌트 enabled가 false가 되고 OnDisable을 호출하지만, 호출 반환 직후 GameObject의 activeSelf·activeInHierarchy와 참조는 아직 유지됩니다. 최종 제거 단계에서는 삭제 루트의 자체 활성 값을 내리고 자식의 자체 값은 보존하며, 계층 활성 상태를 갱신한 뒤 OnDestroy를 한 번 호출합니다.

활성 객체의 disabled 컴포넌트는 Awake 이후 OnDestroy만 받는 경우를 검증했습니다. 한 번도 활성화되지 않은 객체는 Awake·OnEnable·Start·OnDisable·OnDestroy가 실행되지 않았습니다. Awake 내부 전체 삭제는 OnEnable·Start·Update를 실행하지 않는 흐름을 대조했습니다.

Update에서 생성한 컴포넌트의 늦은 Start 안에서 전체 삭제를 요청하고 OnDisable에서 다시 enabled·GameObject를 활성화하는 경우도 대조했습니다. 검사한 Unity 흐름은 첫 관찰 시점에 재활성화된 참조를 유지하고, 다음 Update 전 제거 과정에서 다시 OnDisable·OnDestroy를 호출합니다. 일반 삭제의 현재 Tick 이후 처리와 이 늦은 Start 경로를 분리했습니다. 이는 검사한 프레임 관찰 지점의 동등성이며 모든 렌더 단계·콜백 조합의 동등성을 뜻하지 않습니다.

활성 스크립트 프리팹을 초기 Awake·Start에서 Instantiate하고 내부 컴포넌트 참조, 호출 반환 때의 Awake·OnEnable 및 Start 보류, 첫 Update와 이후 전체 삭제를 검증했습니다. 삭제 대기·시작 배치·재진입의 임시 태그는 복제본에서 정리합니다. 비활성 프리팹·OnDisable 내부 복제의 검증 범위는 위 절을 참고하십시오. 그 외 모든 콜백 조합과 자산 자체 삭제·재부모화·부활 동작은 아직 미검증입니다.

초기 실행 순서와 활성 콜백 재진입

작성된 사용자 C++ 스크립트의 초기 Awake·OnEnable과 Start를 MonoImporter의 명시적 Script Execution Order 순서로 처리합니다. 초기 Awake·OnEnable을 모두 처리한 뒤 Start를 실행하며, 상속된 콜백과 명시적 부모 호출도 유지합니다. 비활성 객체는 이 배치에서 초기화하지 않고 실제 활성화까지 보류하며, 런타임 추가·복제 객체는 즉시 초기화하는 경로를 사용합니다. 동일 순위 사이의 순서는 보장하지 않습니다.

검증 프로젝트는 두 객체를 실행 순서와 반대로 배치하고 -100·100을 지정했습니다. 먼저 실행되는 객체는 다른 객체의 Awake·OnEnable·Start 횟수를 0으로, 나중 객체는 1로 읽는지와 전체 콜백 순서를 대조합니다. Update 제어 객체에는 -1000을 지정합니다.

OnEnable에서 자기 enabled를 false로 바꾸는 경우와 OnDisable에서 자기 enabled를 true로 되돌리는 경우를 검증했습니다. GameObject의 OnEnable 중 비활성화도 처리합니다. GameObject 비활성화 콜백 안에서 재활성화를 요청하면 Unity는 메시지를 기록하고 activeSelf=true·activeInHierarchy=false 상태로 남을 수 있습니다. 이때 불필요한 OnEnable을 호출하지 않고, 이후 SetActive(true) 요청에서 계층을 다시 활성화하도록 맞췄습니다.

임시 시작 배치·재진입 상태는 복제 객체에서 정리합니다. 이 조합 자체의 모든 복제·부모 변경·삭제 동등성을 검증했다는 뜻은 아닙니다. 동일 순위의 객체, 임의 동적 초기화 순서, 깊은 재진입과 다른 객체를 변경하는 모든 조합, 물리·UI·애니메이션의 모든 조합은 아직 확인 범위 밖입니다.

첫 실행에서는 Unreal이 Instantiate한 프레임부터 중력을 적용해 Unity보다 한 물리 단계 앞섰습니다. 변환 스크립트의 Update를 물리 처리 이후 단계로 옮겨 생성 프레임의 위상을 맞췄습니다. 서로 충돌하지 않는 무감쇠 자유낙하 테스트에는 위치 0.0001m, 속도 0.0001m/s 기준을 적용했습니다. 기존 지면 접촉·250프레임 검사의 별도 물리 해석 오차 기준은 유지하며, 두 엔진의 모든 물리 상황이 동일하다는 뜻은 아닙니다.

비활성 루트의 Rigidbody를 복합 충돌체로 잘못 판정한 내보내기 검사도 수정했습니다. 복합 충돌체·비지원 축/모드·임의 물리 API와 충돌 콜백, 물리와 애니메이션/UI를 함께 복제하는 모든 조합은 여전히 미지원 또는 미검증입니다. 런타임 Transform 애니메이션 프리팹은 위 절의 범위에서 지원합니다. UI 프리팹 실행 연결은 별도 구현 항목입니다.

프리팹 정의 간 연쇄·순환 참조

사용자 스크립트의 GameObject 필드가 다른 기본 프리팹 자산의 루트를 가리키는 경우를 지원합니다. 장면에서 A만 참조하더라도 A→B→C→A처럼 연결된 정의를 수집하며, 방문한 자산은 한 번만 구성합니다. 대상이 없는 참조는 가져오기 전에 차단합니다. 중첩 프리팹이나 Variant와는 별개의 자산 필드 참조입니다.

Unreal에서는 같은 장면 안의 비실행 프로토타입을 서로 연결합니다. 생성된 객체에서 다음 프리팹을 조회·생성하고, 순환 경로를 돌아 같은 유형을 다시 생성해도 내부 루트·컴포넌트 참조는 새 복제본으로 연결합니다. Unity가 자기 자신을 가리키는 필드를 저장할 때 내부 루트 참조로 직렬화하는 경우에는 그 내부 참조 의미를 보존합니다. 실제 자산 참조와 내부 참조는 내보낸 종류에 따라 구분합니다.

Unity 복원은 먼저 프리팹 자산의 경로와 식별자를 등록한 뒤 내용을 채우므로, 매니페스트 순서와 무관하게 앞방향·순환 참조를 복원합니다. 복원 후 실제 실행과 재내보내기로 참조·상태를 대조합니다. 비교식 안의 상태 변경 없는 사용자 컴포넌트 GetComponent 조회를 지원하며 AddComponent 같은 상태 변경 호출의 평가 순서 제한은 유지합니다. 런타임 물리 프리팹은 위 절의 범위를 참고하십시오. Transform 애니메이션은 위 절의 범위에서 지원합니다. UI 구성, 중첩·Variant 및 임의 API는 별도 미지원 범위입니다.

비활성 프리팹과 OnDisable 내부 복제

메시·사용자 스크립트로 구성된 비활성 루트·자식 프리팹의 런타임 생성을 지원합니다. 물리 구성은 위 절의 검증 범위에서 추가 지원합니다. 지원 Transform 애니메이션은 위 절의 범위를 참고하십시오. UI·카메라·라이트·Volume을 포함한 런타임 프리팹은 사전 검사를 유지합니다.

실제 Unity 기준으로 비활성 프리팹 생성 직후에는 Awake·OnEnable·Start가 실행되지 않습니다. 루트를 활성화하면 해당 루트의 Awake·OnEnable이 실행되고, 비활성 자식은 자신의 활성화까지 대기합니다. 이미 실행한 객체를 비활성 상태에서 복제하면 공개 필드 값은 복사하지만, 엔진 내부 초기화 상태는 새로 시작합니다. 따라서 공개 Awake·Start 카운터도 이후 콜백에서 다시 증가합니다.

GameObject 삭제 요청의 OnDisable 안에서 복제한 객체와, 계층 비활성화의 OnDisable 안에서 복제한 객체를 실제 실행으로 대조했습니다. 삭제 대기·계층 처리의 임시 태그를 복제본으로 전파하지 않고, 공개 필드와 내부 GameObject·컴포넌트 참조를 복제본으로 연결합니다. 검사한 재활성화·재삭제 흐름의 동등성이며 임의 깊이의 재귀 복제·모든 다른 콜백 조합은 미검증입니다.

GameObject 전체 삭제와 초기 프리팹 복제

Destroy(GameObject)는 컴포넌트 단독 삭제와 구분합니다. 검사한 활성 객체는 삭제 요청 안에서 컴포넌트 enabled가 false가 되고 OnDisable을 호출하지만, 호출 반환 직후 GameObject의 activeSelf·activeInHierarchy와 참조는 아직 유지됩니다. 최종 제거 단계에서는 삭제 루트의 자체 활성 값을 내리고 자식의 자체 값은 보존하며, 계층 활성 상태를 갱신한 뒤 OnDestroy를 한 번 호출합니다.

활성 객체의 disabled 컴포넌트는 Awake 이후 OnDestroy만 받는 경우를 검증했습니다. 한 번도 활성화되지 않은 객체는 Awake·OnEnable·Start·OnDisable·OnDestroy가 실행되지 않았습니다. Awake 내부 전체 삭제는 OnEnable·Start·Update를 실행하지 않는 흐름을 대조했습니다.

Update에서 생성한 컴포넌트의 늦은 Start 안에서 전체 삭제를 요청하고 OnDisable에서 다시 enabled·GameObject를 활성화하는 경우도 대조했습니다. 검사한 Unity 흐름은 첫 관찰 시점에 재활성화된 참조를 유지하고, 다음 Update 전 제거 과정에서 다시 OnDisable·OnDestroy를 호출합니다. 일반 삭제의 현재 Tick 이후 처리와 이 늦은 Start 경로를 분리했습니다. 이는 검사한 프레임 관찰 지점의 동등성이며 모든 렌더 단계·콜백 조합의 동등성을 뜻하지 않습니다.

활성 스크립트 프리팹을 초기 Awake·Start에서 Instantiate하고 내부 컴포넌트 참조, 호출 반환 때의 Awake·OnEnable 및 Start 보류, 첫 Update와 이후 전체 삭제를 검증했습니다. 삭제 대기·시작 배치·재진입의 임시 태그는 복제본에서 정리합니다. 비활성 프리팹·OnDisable 내부 복제의 검증 범위는 위 절을 참고하십시오. 그 외 모든 콜백 조합과 자산 자체 삭제·재부모화·부활 동작은 아직 미검증입니다.

초기 실행 순서와 활성 콜백 재진입

작성된 사용자 C++ 스크립트의 초기 Awake·OnEnable과 Start를 MonoImporter의 명시적 Script Execution Order 순서로 처리합니다. 초기 Awake·OnEnable을 모두 처리한 뒤 Start를 실행하며, 상속된 콜백과 명시적 부모 호출도 유지합니다. 비활성 객체는 이 배치에서 초기화하지 않고 실제 활성화까지 보류하며, 런타임 추가·복제 객체는 즉시 초기화하는 경로를 사용합니다. 동일 순위 사이의 순서는 보장하지 않습니다.

검증 프로젝트는 두 객체를 실행 순서와 반대로 배치하고 -100·100을 지정했습니다. 먼저 실행되는 객체는 다른 객체의 Awake·OnEnable·Start 횟수를 0으로, 나중 객체는 1로 읽는지와 전체 콜백 순서를 대조합니다. Update 제어 객체에는 -1000을 지정합니다.

OnEnable에서 자기 enabled를 false로 바꾸는 경우와 OnDisable에서 자기 enabled를 true로 되돌리는 경우를 검증했습니다. GameObject의 OnEnable 중 비활성화도 처리합니다. GameObject 비활성화 콜백 안에서 재활성화를 요청하면 Unity는 경고를 기록하고 activeSelf=true·activeInHierarchy=false 상태로 남을 수 있습니다. 이때 불필요한 OnEnable을 호출하지 않고, 이후 SetActive(true) 요청에서 계층을 다시 활성화하도록 맞췄습니다.

임시 시작 배치·재진입 상태는 복제 객체에서 정리합니다. 이 조합 자체의 모든 복제·부모 변경·삭제 동등성을 검증했다는 뜻은 아닙니다. 동일 순위의 객체, 임의 동적 초기화 순서, 깊은 재진입과 다른 객체를 변경하는 모든 조합, 물리·UI·애니메이션의 모든 조합은 아직 확인 범위 밖입니다.

부모 변경과 초기 Awake/Start 내부 생성·삭제

Transform.SetParent(parent), SetParent(parent, worldPositionStays)와 transform.parent = null의 부모 해제를 지원합니다. 활성·비활성 부모 사이 이동 후 activeSelf를 보존하고 activeInHierarchy·OnEnable·OnDisable·Update 상태를 갱신합니다. 월드 좌표 유지와 로컬 좌표 유지 옵션, 월드·로컬 위치와 회전을 함께 대조했습니다.

초기 Awake 또는 Start 안에서 비활성 객체를 만들고 사용자 컴포넌트를 추가·설정한 뒤 활성화하는 흐름을 검증했습니다. 생성 호출이 반환될 때 Awake·OnEnable은 실행됐지만 Start는 아직 실행되지 않습니다. 첫 Tick 전에 생성한 컴포넌트의 Start를 첫 Update 전에 처리하여 같은 프레임부터 Update가 실행되도록 합니다. Update 도중 생성한 경우에는 기존처럼 현재 Tick 뒤에 Start를 처리하고 다음 프레임부터 Update를 실행합니다.

Destroy(this)로 컴포넌트를 자기 삭제할 수 있습니다. 검증한 활성 컴포넌트의 Awake 내부 삭제는 Awake→OnDisable→OnDestroy 순서이며 OnEnable·Start·Update는 실행하지 않습니다. Start 내부 삭제는 Awake→OnEnable→Start→OnDisable→OnDestroy 순서이고 Update는 실행하지 않습니다. OnDisable은 삭제 요청 안에서 호출하고 실제 제거·OnDestroy는 해당 프레임의 Tick 이후 처리합니다.

이 범위는 초기 생성과 검사한 부모 변경 흐름에 대한 실행 검증입니다. 초기 실행 순서와 재진입은 해당 항목의 확인 범위를 참고해 주세요. 그 밖의 상호·재진입 콜백, 잘못된 순환 부모 지정, 임의 생성 단계와 모든 물리·UI·애니메이션 조합의 동등성은 아직 미검증입니다.

스크립트 식별자와 실행 순서

원본 MonoScript의 GUID와 Editor의 Script Execution Order 값을 내보내어 Unreal 프로젝트의 스크립트 정의에 보존합니다. C# 복원 시 같은 GUID와 executionOrder를 가진 .meta를 생성하며, 대상 자산이 이미 그 GUID를 사용하면 충돌로 중단합니다. 메타데이터가 없는 이전 패키지도 계속 복원할 수 있습니다.

Unreal의 작성된 사용자 C++ 스크립트는 명시적 실행 순서에 따라 초기 Awake·OnEnable을 처리한 뒤 Start를 정렬 실행합니다. Update도 낮은 순위의 Actor를 Tick 선행 조건으로 사용합니다. 런타임 AddComponent에도 해당 클래스의 순서 설정을 전달합니다. 동일 순위·임의 동적 생성·모든 재진입 조합의 실행 동등성은 별도 검증 범위이며, 명시적 순서가 있는 원본을 내보낼 때 이 범위를 안내합니다.

Unity 6000.0 공식 문서에 따르면 같은 값이나 기본값을 사용하는 스크립트 사이의 실행 순서는 비결정적입니다. 활성 계층 테스트는 제어 스크립트에 -100, 나머지 스크립트에 0을 명시합니다. 순서를 명시하기 전후의 원본 Unity 결과가 동일함을 대조한 뒤 포팅·역변환·패키징 실행을 비교합니다. 임의 기본 순서의 프레임별 결과를 동일하게 보존한다고 보장하지 않습니다.

GameObject 활성 상태와 비활성 계층

GameObject.SetActive(bool), activeSelf와 activeInHierarchy 조회를 네이티브 Actor 코드로 변환하고 다시 C#으로 복원합니다. 작성 시 비활성인 장면 객체와 부착 스크립트·참조도 함께 전달합니다. 원본 프로젝트는 수정하지 않습니다.

GameObject 자체의 activeSelf는 해당 객체의 태그로 보존하고, activeInHierarchy는 부모 계층과 활성화 진행 상태를 반영합니다. 부모가 비활성이어도 자식의 activeSelf는 유지됩니다. 계층이 실제 활성 상태로 전환될 때 스크립트의 Awake·OnEnable을 호출하고 Start를 지연 실행합니다. 비활성 객체에 AddComponent로 추가한 스크립트도 첫 활성화까지 Awake를 보류합니다. 비활성화는 OnDisable을 동기 호출하고 Update를 중지하며, 재활성화한 프레임의 Update는 보류합니다.

검증 시나리오는 부모 토글, 부모가 비활성일 때 자식 자체 토글, 반복 동일 값 설정, 같은 프레임 false→true, 작성 시 비활성 객체의 최초 활성화, disabled 컴포넌트와 계층 활성 상태 조합, 비활성 런타임 객체에 컴포넌트 추가 및 삭제입니다. 객체의 일반 활성/비활성 상태는 메시 표시와 Actor 충돌 상태에도 연결됩니다. 모든 종류의 물리·UI·애니메이션 컴포넌트 토글, 검사한 경우 외의 활성 콜백 재진입·상호 호출, 비활성 프리팹 생성은 아직 실행 검증 범위 밖입니다.

OnEnable/OnDisable과 컴포넌트 enabled

사용자 MonoBehaviour의 OnEnable·OnDisable, 자기 자신과 다른 컴포넌트의 enabled 읽기·단순 대입을 추가했습니다. 작성 시 disabled인 컴포넌트도 플래그와 참조를 저장·재열기·역변환합니다. GameObject의 활성 상태와 계층 전파는 아래 SetActive 지원 범위를 참고해 주세요.
